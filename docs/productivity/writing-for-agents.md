## What it does

`writing-for-agents` helps keep instructions scoped and references conditionally disclosed. It preserves non-obvious constraints and removes generic teaching; it is not a mandatory preflight for every document edit.

## When to reach for it

Invoke `/writing-for-agents` explicitly when instruction scope or organisation needs attention. Existing callers can read it as a reference when that specific writing decision arises; ordinary edits do not auto-start it.

## The useful pointer

A **[context pointer](https://www.aihero.dev/ai-coding-dictionary/context-pointer)** names the material and when to read it. Shared constraints stay inline; substantial branch-specific detail sits behind a link. A short single-purpose document does not need an extra layer.

The skill-mechanics reference is needed only when changing discovery, invocation policy, or routers. It distinguishes automatic selection from reading a file, and does not promise identical behaviour across hosts.

## Common questions

**Does trimming mean removing capability or safety constraints?**
No. Keep scope, permissions, runtime contracts, and observable completion conditions. Remove repetition and basic teaching, not the information needed to do the task correctly.

**Where did `writing-great-skills` go?**
It became `writing-for-agents`. The reference applies beyond skills, but that does not make every document edit a reason to load it.

## It's working if

- A branch can find its reference and still knows the task boundary.
- Routine edits do not load a chain of unrelated guides.
- Completion can be checked from the result, not just from prescribed wording.

## Where it fits

A standalone explicit writing reference, not an extra stage in the engineering chain. For the whole map, see [ask-matt](https://aihero.dev/skills-ask-matt).
